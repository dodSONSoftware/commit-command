## Resolution and transport behavior

Committed `./` and `../` declarations resolve with repository-directory semantics against the **explicit parent destination selected by the recorded observation/local preview**. The declaration, resolution base and effective child destination are displayed. GitFleet does not silently choose the ambient branch remote, origin, child URL override or local directory as a base. An operator choosing another parent destination chooses another deployment context, and child evidence still requires a separately approved observation of the exact resolved child destination. Historical mapping blobs/source IDs and existing freshness/context checks continue to bind the selection.

The pure resolver handles supported HTTPS/SSH/file URLs, absolute local fixture paths, and supported SCP bases. It preserves scheme, authority, explicit SSH port and login, and refuses traversal beyond authority/filesystem/home roots. Relative remainders and SCP paths use a bounded plain ASCII path envelope; embedded dot-segment, encoded-path, query/fragment, backslash, option-like or otherwise ambiguous spellings refuse. This is a deliberately bounded supported subset, not every URL Git can interpret. Names needing unsupported spelling should use an explicitly reviewed supported URL or remain blocked; there is no lossy rewrite fallback.

Supported SCP syntax requires a plain explicit login, host (including bracketed IPv6) and repository path. `git@host:team/repo.git`, `git@host:/team/repo.git` and explicit tilde forms remain **SCP strings** in inspection, assignment, review, transport and evidence. A home-relative SCP path is never rewritten as absolute `ssh://.../team/repo.git` or `ssh://.../~/team/repo.git`: those change the path sent to an SSH server and may not be equivalent for a hosting service's forced command. Missing login is not inferred from the OS or a profile. SCP supplies no port syntax; nondefault ports require explicit `ssh://user@host:port/path` URLs. Exact spelling is required when comparing SCP destinations with child observations; no speculative equivalence is granted across URL forms.

SCP validation was added to the existing dedicated SSH transport without relaxing selected agent/public identity, protected known-hosts, strict host verification, disabled SSH config/proxy/fallback/forwarding, separate native review or cancellation requirements. The read-only Git adapter retains its protocol bans. No new background network/authentication operation was added.

Primary references: [Git submodule directory/base semantics](https://git-scm.com/docs/git-submodule), [Git URL forms](https://git-scm.com/docs/git-clone#_git_urls), [Git 2.56 relative URL implementation](https://github.com/git/git/blob/v2.56.0/remote.c), and [Git SSH URL parsing](https://github.com/git/git/blob/v2.56.0/connect.c). GitFleet's explicit selected base is a product policy; these sources establish directory and transport syntax, not implicit authority to contact a historical URL.

Consequently a direct SCP/default-port end-to-end connection is not claimed. The real SSH-agent case uses an explicit high-port SSH URL, and the SCP-specific acceptance is the independent Git parser and application tests. A future suitable isolated port-22 host/operator can close that remaining transport acceptance case.
