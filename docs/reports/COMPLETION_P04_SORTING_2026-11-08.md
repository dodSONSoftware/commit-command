# Completion P04 sortable overview checkpoint

The overview now supports both directions for repository name/path, branch/HEAD, staged/unstaged/untracked/conflicts, cached ahead/behind, last commit time, inspected trust and error/status. Each specified table header is a button with aria-sort; the menu also supports repository-name sorting and retains the legacy Changes option. Conflict counts and numeric cached ahead/behind columns are visible alongside the existing detailed remote-status presentation. Last commit shows labeled committer time; observation time remains separately labeled. Unknown status now displays Not observed; issues are never mislabeled Clean.

Sort rules are explicit: numbers use numeric order; text uses case-sensitive code-point order independent of machine locale; last commit uses committer time; trust uses the inspected validity text; error/status uses the displayed status category. Missing observations sort last in either direction. Equal values always break ties by displayed full path, then stable worktree ID ascending, regardless of selected direction or inventory arrival order. Cached upstream comparisons do not claim current server knowledge. Sorting/filtering copies the visible list and never changes explicit selection.

Core's OverviewSort enum adds serialized string values without rewriting version-1 navigation records or adding a database schema. Existing path and changes values deserialize unchanged; changes retains descending staged+unstaged semantics. Unknown values fail deserialization before persistence. Generated request/response contracts share the enum. New direction roundtrips through SaveState/LoadState across actual Application reopen, preserving drafts and tabs.
