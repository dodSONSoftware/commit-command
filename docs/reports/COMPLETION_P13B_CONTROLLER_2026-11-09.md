# Completion P13B native-confirmed AI import controller

Core now owns one expiring native-file selection and one frozen import preview. The Rust-only register_ai_import entry accepts an absolute native-selected regular/non-symlink file, bounds the captured container to34 MiB, verifies the archive and decodes a frozen metadata snapshot. Request JSON accepts only source/preview tokens, choices and displayed fingerprints; it cannot register a filesystem path or submit a candidate configuration. InspectAiImport returns the frozen source and currently available scopes. Selecting another source revokes previous tokens/reviews even when the new archive is invalid. Sources expire after five monotonic minutes; native review expiry is bounded by remaining source lifetime and checked before issuing/using a confirmation. Tokens are dropped on context reset/shutdown/reopen; they are never persisted or replayed.

PreviewAiImport runs the explicit merge planner, verifies the source again, creates a new opaque preview token and returns exact candidate/entity decisions/unassigned scopes. Any new preview attempt, including invalid choices, revokes the previous preview/review. Available mappings match existing AI editor boundaries: application, active workspace and its available nonsuperseded worktrees. Mapped repositories undergo fresh existing root/Git/common binding inspection. Other source assignments remain unassigned; no name matching or implicit inactive-workspace rebinding occurs.

ReviewAiImport consumes the frozen preview token, checks its digest and rereads source/current settings/identity state. It creates the existing trusted native ReviewDisplay/one-use Rust Confirmation flow, explicitly permitted for separately scoped metadata import in the ordinary inspection build. This does not enable Git writes. Confirmation shows the complete candidate, resolved choices, unassigned scopes and exact archive/preview hashes. It authorizes configuration publication only, not provider requests, credential-store access, Git writes, hooks, Actions or automatic runs. The host’s active controlled-write guard now includes import preview/review; native source selection is not yet wired to a host picker or renderer UI.

Apply refuses while AI work remains queued/running or cancellation is still being handled. A private finished marker prevents a cancelled display phase from falsely proving that its owned worker has stopped. Apply then revalidates source/current metadata/mapped identities, publishes and verifies an AI-only safety export under owned0700 ai-import-safety, revalidates again and checks cancellation before existing atomic settings-generation publication. Imported authentication/approvals remain reset. Old complete generations and the safety archive remain; successful apply updates scheduler limits and revokes import tokens. No provider call or durable SQL schema change occurs. Cancellation before publication stops; once atomic publication starts, a complete new generation may finish. Existing store publication errors never imply that a mixed generation is active; actual post-pointer crash/fsync recovery acceptance remains open.
