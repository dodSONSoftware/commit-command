# Completion P13A private archive publication checkpoint

`backup::publication::Destination` now holds a directory descriptor and creates private exclusive UUID staging files. Opening the destination walks each absolute path component with O_NOFOLLOW/O_DIRECTORY; the final directory must be user-owned and private, checked again when publishing. All temporary and final operations are descriptor-relative. Traversal/control/reserved staging names, existing names and symlink destinations are refused.

Publication writes the bounded archive, syncs the file (including macOS F_FULLFSYNC), validates it through a separately opened descriptor, verifies staging inode/device/ownership/mode/link count, then atomically creates a new final name with same-directory linkat. Existing names are never replaced. It removes only its own matching temporary inode and syncs the directory before returning success. An error after final-name creation may leave a verified complete archive; callers must report uncertainty/failure and never rotate on that result. Cleanup failure leaves an inert `.tmp`, which is never interpreted as a successful backup.

Sixteen focused backup tests and strict all-feature/all-target Core Clippy passed. New cases verify exact existing destination preservation, mode 0600/single-link final archives, checksum-valid publication, symlink/nonprivate/traversal refusal, bad source metadata cleanup, cancellation during streaming and injected source read failure. Evidence and source hashes: `docs/validation/completion-p13a-publication-2026-11-08/`.

This remains partial P13A. The storage owner must choose destinations outside managed repositories, capture coherent settings/config/database generations and enforce authority/artifact policy. Disk-space preflight, destination write/fsync failure injection, process-crash boundaries, migration adoption and catalog-complete boundary/native tests remain open. No full backup/import/restore UI, retention or release acceptance is claimed.
