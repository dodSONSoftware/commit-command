# Serialized background refresh and native retest

November 2, 2026. Follow-up to [native lifecycle checkpoint](M3_NATIVE_LIFECYCLE_2026-11-02.md). That session exposed periodic inventory/trust reads filling the bounded Core queue while a controlled write occupied its owner.

## Change

Background polling now awaits the native write status first. While a write runs, it updates the write indicator without queueing inventory/trust reads. Otherwise it awaits inventory and trust serially. One in-flight refresh pipeline is shared across effect lifecycles, so a slow request cannot accumulate more refreshes each interval. Context/liveness checks prevent an old polling cycle from publishing trust/write status/errors after context changes. Errors remain observable. Foreground cancellation and Core queue/authority limits are unchanged.

## Verification
