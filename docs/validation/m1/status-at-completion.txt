# GitFleet implementation status

Updated: 2026-11-01. **M1 complete for the documented local macOS envelope; stopped
for user review.** The user authorized M1 including the proposed decisions and
acceptance gates. M2 and later were not implemented. No commit, push, remote
workflow execution, publication or deployment was performed.

Core remains one Rust crate, independent of presentation technology. Existing
`docs/` and `app/` structure and desktop placeholders remain intact. The user's
pre-existing `.gitignore` modification was preserved. All Git writes during
validation used new temporary fixtures; no existing user repository was written.

## Delivered

- Named single-root saved workspaces with list/create/update/remove, one persisted
  active ID, explicit data directory, atomic TOML and transactional SQLite state.
- Stable repository/worktree UUIDs bound to observed common/per-worktree filesystem
  metadata; separate native identity/display paths; verified moves, distinct copies/
  replacements, no inherited or automatically granted trust.
- Explicit recursive scans with configurable exclusions, partial/error inventories,
  retained missing/unavailable entries, submodule and linked-worktree relationships,
  external references without expansion, and targeted status refresh without rescan.
- Structured porcelain-v2 status, partial staging/renames/conflicts/modes/gitlinks,
  unborn/detached HEAD, operation markers, last commit and local-only upstream data.
- Bounded history pages, actual parent OIDs, refs/tags, commit bytes/timestamps,
  shallow boundaries, and stale-cursor detection.
- Staged/unstaged/parent/root diffs, literal paths, immutable blobs, binary/mode/
  symlink/gitlink summaries and bounded previews.
- Bounded/cancellable read transport, four subprocesses, one multi-command read per
  worktree, consistency checks, private clean Git environment, helper restrictions.
- Native-argument JSON CLI, typed failures, acceptance evidence and updated handoff.

Architecture, API details, limits and explicit unsupported configurations are in
[M1 contracts](architecture/M1_READ_ONLY_WORKSPACES.md). Core command examples are
in [the core README](../app/core/README.md).

Its runners must provide Git/Rust satisfying the declared floors. Linux and Windows
support remain unclaimed. No cross-platform acceptance was inferred from compilation

## Remaining risks and next boundary

Configured content filters and sparse-index configuration fail closed. Read-only
ordinary/unmerged/split-index and SHA-256 fixtures passed. Non-UTF-8 ref names,
Windows execution/process trees, Linux runtime behavior, network filesystems,
malicious concurrent metadata/config replacement and filesystem confidentiality
through config includes/alternates remain outside validated support. Native kernel
filesystem I/O is not asynchronously cancellable. Safe-policy status can differ
from unrestricted shell Git because system/global config is suppressed.

M1 snapshots detect ordinary changes; they are not an atomic filesystem view or an
OS sandbox. Cached unavailable entries retain last observations with availability/
time labels. Child dirt is reported independently and is not recursively added to
parent counts. No remote freshness or connectivity is implied by ahead/behind.

M2 requires explicit authorization and a bounded plan before work: production trust,
opaque review approvals, full state preflight, hook lifecycle/complete bypass, user
signing configuration, durable journal/scratch integrity and recovery, exact message
verification, shared-worktree concurrency and safe index reconciliation remain open.
