## Remaining risks and M1 readiness

M0 is ready for review; M1 can be scoped after authorization. M1 must establish
stable repository/common-directory/worktree identities and relationship/move rules,
structured status/path/error models, saved-workspace storage, read-only history/diff
policies, and supported Git versions. Config/metadata TOCTOU, process time/output
limits and inaccessible inventory behavior need explicit decisions before expanding
inspection beyond the documented envelope.

Configured content filters are unsupported for untrusted inspection. Hostile
concurrent metadata/config replacement is unsupported; includes/alternates can read
outside the chosen directory. Bare repositories, submodule detail, advanced index
formats, SHA-256, non-UTF-8 metadata/root paths, Linux/Windows and additional Git
versions have no support claim. Missing promisor objects fail without fetching.

Production writes remain blocked on trust/opaque approvals, full unsupported-state
preflight, hook lifecycle and comprehensive bypass, normal signing configuration,
journal/scratch integrity and durability/cleanup, index flags/extensions, worktree
concurrency, exact message enforcement and post-hook state revalidation. Existing
crash tests do not cover every transaction boundary or power loss.
